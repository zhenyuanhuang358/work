# 决策卡（把事前约束固化下来）

目的：让认错线、退出条件在决策发生的那一刻就写下来，并留下可事后对照的记录。没有这张卡，规则 5 只是口号。

## 事前（结论为「做」或「等」时附上；用户确认后才算数）

| # | 项 | 要求 |
|---|---|---|
| 1 | 决策与日期 | |
| 2 | 为什么做 | 一句话，用用户自己的话；写明目的是保值、想赚，还是其他 |
| 3 | 最坏损失 | 金额，以及占可承受亏损的比例 |
| 4 | 认错线或退出条件 | 必须是可观测的事实（价格、占比上限、日期、对方的具体行为），并写明由什么机制自动执行（条件单、合同条款、占比上限、他人监督、冷却期）。不接受「感觉不对就走」 |
| 5 | 否定条件 | 出现什么现象，这个判断作废 |
| 6 | 复核日期 | YYYY-MM-DD |
| 7 | 对照个人规则 | 自己模式：通过，或违反哪一条（以 `tiandao_check.py` 输出为准） |

**硬规则**：
- 用户拒绝写第 4 条，或写不出可观测的事实，结论降为「不做」。
- 不替用户填第 2 条和第 4 条，只提问、只校对。

## 存档

用户确认后，把卡写成 `memory/state/tiandao/cards/YYYY-MM-DD-<短名>.md`，首部带：

```
status: open
review_date: YYYY-MM-DD
mode: self | client
```

`self_check.py` 的 C16 会点名过了复核日、仍为 `open` 的卡。客户模式不存客户的身份信息，短名用代号。

## 事后复盘（到复核日，或触到认错线、否定条件时）

用户把决策卡贴回来（或你从 `cards/` 读到），做三件事：
1. 对照第 2、3、4 条，看实际发生了什么。
2. 归因到判断、仓位、执行三类之一。
3. 指出是否需要修订哪条规则（修订走 personal-rules.md 的修订记录），并把这次作为一个样本记入卡的「复盘」段。

完成后把 `status` 改为 `closed`。
用户没有贴回，你不追问；但下次对话涉及同类决策时，先问上一张卡的结果。
