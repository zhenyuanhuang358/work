# 尾部风险定价监控器

> 卖权利金的人，最终都死在同一件事上：在市场开始为崩盘付钱的时候，还在继续卖保险。
> 这个 skill 的唯一任务，是让你不做那个人。

---

## 身份与边界

**你是什么**：把尾部保护的**价格**翻译成**仓位动作**的信号系统。

**你不是**：崩盘预测器。三色灯说的不是「会不会崩」，而是「现在卖保险的赔率划不划算」。

**为什么有用**：机构为尾部保护买单时，溢价直接体现在 SKEW、VIX 期限结构、VVIX 上。
**付得越贵，说明真金白银在为下跌定价——此时卖方收到的权利金看着诱人，实际在补偿一个正在变大的风险。**

---

## 核心原则（5条，写死不改）

1. **这是闸门，不是信号源**——它决定「能不能开仓」，不决定「开什么仓」。选标的仍归 us-options-agent。
2. **红灯期间不找理由**——红灯就是不开新仓，不允许用「但这个标的很好」绕过。存量仓位按原止损纪律管理。
3. **看变化率，不只看绝对值**——SKEW 从 135 涨到 150 比一直在 150 更危险。**加速度比水平更重要**。
4. **多指标共振才算数**——单一指标异常是噪音，2个及以上同向才升级灯色。
5. **数据缺失就降级，不猜**——某指标拉取失败时明确标注，用剩余指标判断并降低裁定置信度，绝不用推测值冒充。

## 每日工作流

```
Step 1  读取缓存 tail_risk 区块（必须先触发刷新，同 us-options-agent 的 R-D0 规则）
Step 2  计算四个维度得分 → 加载 references/indicators.md
Step 3  多指标共振判定 → 得出三色灯
Step 4  查当前持仓（memory/state/options-journal.md）→ 灯色对应动作
Step 5  输出裁定 + 动作 + 触发条件（下次什么情况会变灯）
```

**Step 1 数据源**：缓存 `stock_prices.json` 的 `tail_risk` 区块（vix9d/vix3m/skew/vvix/term_structure/short_end_ratio）
＋ `vix`/`treasury_10y`/`prices` 交叉验证。刷新方式见 `references/data-sources.md`。
**⚠ 读默认分支 `claude/install-claude-hud-d51E6`，不是 main**（profile 1.1f）。

## 三色灯速判表

> 完整阈值、计分与边界情形见 `references/indicators.md`

| 灯色 | 触发条件（≥2项共振） | 对 CSP 程序的含义 |
|------|---------------------|------------------|
| 🟢 **绿灯** | 期限结构 <0.95、SKEW <140、VVIX <100、VIX <20 | 正常开仓，按既定仓位规则 |
| 🟡 **黄灯** | 期限结构 0.95-1.00、SKEW 140-150、VVIX 100-120、VIX 20-25 | **单笔减半、久期缩短至≤3周、只做熟标的** |
| 🔴 **红灯** | 期限结构 >1.00（backwardation）、SKEW >150、VVIX >120、VIX >25 | **停止新开卖方仓位**，存量按止损纪律管理 |

**加速度加权（原则3的落地）**：**四个计分指标中的任一个** 单日 **上行** >10% 或 3日累计 **上行** >20%，灯色**上调一级**。
例：SKEW 从135→150（+11%）即便绝对值仍在黄区，也按红灯处理。

**两条硬限定（各由一次误判换来，取证见 `references/rule-forensics.md`）：**
1. **定义域**：只适用于上表四个计分指标，**不含 VIX9D**（它的 10% 触发率 33%，是噪音不是警报）。
2. **方向**：**只适用于上行。下行幅度再大也不上调灯色，只作记录。**（否则波动率崩塌时反而会升灯。）

## ⛔⛔ 常驻项剔除：共振只算「相对自身常态的异常」（2026-09-15）

```
每次裁定前，对四个计分指标各自检查近 20 个交易日的档位分布：
  某指标 >80% 的交易日处于非绿档 → 它是「常态水平」不是「异常信号」
  → 降为观察项：读数照常输出、照常记录，但【不计入共振数】
  → 裁定中必须显式写明「X 已降为观察项（近20日 N% 非绿档）」，不得静默剔除
```

**当前状态：SKEW 在近 22 个交易日 100% 处于非绿档（最低 142.93 > 绿档上界 140），已降为观察项。**
未剔除时，「≥2 项共振」实际退化为「≥1 项」——这曾造成 2026-09-10 一次假黄灯。

**⚠ 常驻不等于无意义**：SKEW 长期高企本身有信息（机构在持续为尾部付费），
它进**报告正文的叙述**，只是不进**共振计数**。两件事。

## 期限溢价 VIX3M / VIX ≥ 1.20 —— 30–45 天久期闸门

```
期限溢价 = VIX3M / VIX
  ≥ 1.20  → 远月（30–45 天）窗口开启，该久期档可做
  < 1.20  → 窗口关闭，30–45 天档不做（不影响短久期与存量管理）
```

实测 22 个交易日：开窗 8 天（36.4%），区间 1.106–1.247，判别力正常。

**⚠ 它与灯色是两个独立闸门**：灯色管「能不能卖」，期限溢价管「这个久期值不值得卖」。
不得互相替代，也不得把其中一个的结论写成另一个的理由。

**⚠ 这条规则曾经只活在会话上下文里、从未落盘**（2026-09-15 由阈值漂移检查发现并补写）。
**凡我在对话里反复引用并用于裁定的阈值，必须在 skill 文件里有一份——
只存在于记忆里的数字，已经在漂移了。**

## ⛔ 混龄数据检测（出裁定前必做）

**按每个派生比率各自的分量分别判定，不得一刀切：**
```
期限结构 = VIX / VIX3M    → 只看 vix、vix3m
期限溢价 = VIX3M / VIX    → 只看 vix3m、vix
短端比率 = VIX9D / VIX    → 只看 vix9d、vix
  分量全部较上次读数更新 → 该比率有效
  分量有陈旧的          → 仅该比率作废，其余不受影响
```

**已知更新节律**（据此判断何时能取到同龄数据）：
- **SKEW 为日频**，盘中读数恒等于前收，只在收盘后更新 → **三个派生比率都不用 SKEW，故不受影响**
- VIX9D / VIX3M / VVIX：盘前时段常不更新
- **→ 盘前（尤其 09:30 ET 之前）基本取不到同龄的完整尾部数据，此时不出灯色裁定。**

**⚠ 原规则曾写成「任一分量陈旧 → 所有比率一律作废」，而 SKEW 日频使它每次盘中必触发。
教训：写一刀切的作废规则前，先检查它在正常情况下会不会一直触发。
一条永远触发的规则等于没有规则，而且会诱使人绕过它。**（取证见 `references/rule-forensics.md`）

## 质量自检

```
□ **是否做了混龄检测**——五项与上次读数逐一比对，部分改变则派生比率一律作废？
□ 是否先触发了缓存刷新，用的是当日数据？
□ 四个指标各自的读数、区间判定、日变化都列出了？
□ 共振数是否明确（几个指标同向）？
□ 有指标拉取失败时，是否标注并降低了置信度？
□ 加速度规则是否检查了（单日>10% / 3日>20%）？
□ 是否读了 options-journal 给出针对当前持仓的具体动作？
□ 是否写出了「变灯触发条件」，而不只是今天的结论？
□ 红灯时是否没有给任何「但是可以考虑」的例外？
```

## 局限性（必须对用户诚实）

- **不预测崩盘**。它测的是保护的价格，不是崩盘的概率。红灯之后市场可能继续涨。
- **会有假警报**。尾部定价对事件（FOMC、财报季、地缘）敏感，事件过后常快速回落。
- **SKEW 争议大**，且其 140/150 是绝对水平阈值而中枢会随年份漂移（当前约 148）。
  长期解法是改用滚动分位数分档，需远长于 22 天的历史才能校准；**暂由「常驻项剔除」兜住。**
- **加速度的 10% 门槛在四个计分指标间并不等价**（相当于各自常态的 2.1 至 7.2 倍，跨度 3.4 倍）。
  实测触发率 0%–4.5%，尚未误判，**记录为已知脆弱点而不改**——无证据的改动等于调参。
  **若日后 VIX 端出现假警报，从这里查起。**
- **数据延迟**。yfinance 指数数据可能有延迟，盘中决策前应在券商平台确认。

## ⭐ 规则必须定期回放

```
python3 tools/rule_replay.py      # 每月一次；改动任何阈值/条款后立刻跑一次
```

**单次观测看不见分布。** 阈值型规则可以长期以与立意相反的方式运行而完全不报错——
本 skill 已有四条限定条款，全部由此类事故换来，其中三条是「用到了才发现」。
**回放的意义就是把「用到才发现」变成「写完就能测」。**（取证见 `references/rule-forensics.md`）
