# Layer 1 独立选股器 — 指标、阈值与运行规范

> 由 SKILL.md 在 `Burry 扫描`、或需要改筛选指标/阈值/排查抓数时加载。
> **本模块与归因模块完全解耦**：不使用 13F 数据，只借用选股标准扫全市场。

---

## 设计前提

**「绝对便宜」这个概念跨周期成立，但衡量便宜的具体数字不成立。**
2000 年的 6 倍 EV/EBITDA 和 2026 年的 6 倍不是一回事。

→ **一律用分位数阈值，不用固定倍数。** 分位数随全市场分布自动重新校准，固定数字过几年就得手动调。
**这是用结构解决问题，不是打补丁。**

---

## 两段式流程（价格是瓶颈，不是数据源问题）

```
Stage A — 纯 EDGAR，零价格请求
  EBITDA = 营业利润 + 折旧摊销
  净负债 = 短期借款 + 长期借款 - 现金及等价物
  过滤：净负债/EBITDA ≤ 全市场 60% 分位（低杠杆优先）
        SBC/营收       ≤ 全市场 50% 分位（低稀释）
        数据完整度      ≥ 必需科目的 80%
  预期输出：数百家

Stage B — 只对 Stage A 幸存者取价格
  市值 = dei:EntityCommonStockSharesOutstanding × 价格
  EV   = 市值 + 净负债
  算：EV/EBITDA、P/B、FCF yield
  排序：按硬过滤通过项数，再按 EV/EBITDA 分位升序
```

**若 Stage A 幸存者 > 800 家 → 收紧 Stage A 门槛，不要加大取价量。**

## 筛选指标

| 指标 | 公式 | 阈值（分位数） | 逻辑 | 校准参考 |
|---|---|---|---|---|
| **EV/EBITDA** | 企业价值 / EBITDA | **最低 10% 分位** | 绝对便宜，不比同行 | — |
| **FCF Yield** | 自由现金流 / 企业价值 | **最高 15% 分位** | 现金生成优先于账面利润 | IBA 案例量级：约 2 倍 ex-cash 利润 |
| **P/B** | 市值 / 账面净资产 | **最低 15% 分位** | Graham 式资产安全边际 | Pillowtex 案例量级：约 0.5 倍 |
| **SBC 稀释率** | 股权激励费用 / 营收 | **低于中位数** | 防止账面 EPS 被稀释掩盖真实每股价值 | 2026 年新增过滤条件 |
| **净负债/EBITDA** | 净负债 / EBITDA | **低于 60% 分位** | 偏好低债务资本结构 | — |

**⚠ 校准参考栏的两个案例量级只作方向参考，不得直接写成硬阈值。**
它们是特定年代特定标的的实际值，把它们固化成常量，就退回到了「固定倍数」的老问题。

---

## ⚠ 分位数的样本偏差（本模块最容易出错的地方）

**分位数只能在「有完整 XBRL 数据」的样本内计算。而缺数据的公司系统性偏向小盘股与新上市公司——
这一群体恰好也系统性偏便宜。把它们排除在分位数计算之外，会把「便宜」的门槛整体抬高。**

**处理规则：**
```
缺数据公司 → 标注「数据不完整」，单列成组
             既不参与分位数计算（会污染分布）
             也不剔除（会让筛选范围因数据质量被动收窄）
```

**每次扫描输出必须报告：完整样本 N 家 / 不完整样本 M 家 / M 占比。**
**M 占比若超过 30%，分位数阈值的代表性存疑，须在输出中显式警告。**

> **元教训（来自 Sleeper 建设期的实际事故）**：
> 任何「检测到异常就把异常数据删掉」的修法，都要问一句
> **「删完之后剩下的样本，还代表原来的问题吗」**。
> Sleeper 当时因为删掉基期污染样本，制造了窗口选择偏差，
> 把 SYY 的真实值 5.18% 算成了 16.6%。同一个坑不踩第二次。

## 排序与输出

### 排序方式：先硬过滤，后决定要不要打分
**先用硬过滤（必须同时满足 N 项标准），观察通过筛选的标的数量级是几十还是几百，
再决定要不要转成加权打分。**

**理由：直接上加权打分，会在还没验证过筛选力度之前就引入过多主观权重。**
权重是拟合工具，在没有验证集的时候引入权重 = 把主观判断伪装成算法。

| 通过数量级 | 下一步 |
|---|---|
| < 20 家 | 门槛过严，放宽到 4 项必过 |
| 20–100 家 | **理想区间**，直接人工过一遍，不引入打分 |
| > 100 家 | 收紧到 5 项全过；仍过多再考虑加权打分 |

### 每个标的的输出字段
```
代码 / 名称 / 行业（仅展示，不作为筛选变量）
通过了哪几项标准（逐项列出，不给总分）
每项的具体数值 + 所处分位
数据完整度：完整 / 不完整（缺哪些科目）
```

**行业只展示不筛选**——呼应「不设行业限制」的原则。
**不给总分**——总分会诱导使用者跳过逐项检查。

## 运行频率

**跟随 10-Q / 10-K 披露节奏做季度扫描，不追求实时。**
伯里本人的方法论也不依赖高频信号；季度以内的价格波动不改变「绝对便宜」的判断。

Actions 排程：每季度财报季结束后各跑一次（约 3/1、5/15、8/15、11/15），
加 `workflow_dispatch` 供 `Burry 扫描` 手动触发。

## 与归因模块的可选接口（`Burry 校验`）

两个模块**解耦运行**，但可以做一次性校验：

```
把归因模块产出的「伯里当期实际持仓」
与扫描器同期输出做对比，看有多少重合
```

**这是用来验证筛选器是否真的复现了他的标准，
不是把伯里的持仓当作扫描器的输入。**

### 重合度的读法（不要过度解读）
| 重合度 | 读法 |
|---|---|
| **0 家** | 筛选逻辑可能偏离，或他当期持仓由 L2/L4 因素主导（特殊情形、宏观对冲） |
| **1–3 家** | 正常。L1 是必要不充分条件，全市场同样便宜的有几百家 |
| **大量重合** | **可疑**。应先怀疑是不是无意中用了后见之明（例如阈值被朝着他的持仓调过） |

**⚠ 校验只跑一次，不作为调参依据。**
拿重合度去反向调阈值 = 用后见之明拟合，会得到一个只能解释过去的筛选器。
