# 苗头期复盘：说过「明天可能爆」的，到期必须回来对答案

**何时读**：每次扫描的**第 0 步**（先把已到期的条目记分）和**最后一步**（登记今天的苗头）。
**登记表**：`memory/state/viral-review.md`。表的结构和 `predictions.md` 一样，但单独成表，原因见那份文件的开头。
**来源**：借鉴 [new-term-radar](https://github.com/zhuyansen/new-term-radar) 的 14 天复盘，每个信号都统计命中率和提前天数；判定口径按中文平台改写（2026-10-13 引入）。

---

## 为什么必须有这一步

报告末尾的「明日观察预警」每天都在下判断，但过去从来没有回头核对过。
**说了不核对，就永远不知道「苗头期」这一档有没有信息量**：它可能比随手挑的话题更容易爆，也可能和随手挑的一样。
按 CLAUDE.md 的规定，带门槛和验证时点的判断必须登记，**没有门槛和时点的就不要说出口**。所以苗头只有两种处理：登记，或者不写。

## 登记：每个苗头写成一句可以被证伪的话

```
| 登记时间 | 话题（检索用写法） | 门槛 | 验证时点 | 把握 | 状态 |
| 2026-10-13 10:00 | 「XX品牌 涨价」 | 进入四榜任一前 50 | 2026-10-20 24:00 | 低 | 待验 |
```

- **门槛统一用一个**：验证窗口内进入 **微博热搜 / 抖音热榜 / 百度热搜 / 知乎热榜** 任一榜单的前 50。
  只认这一种读法，登记时就定死（同 predictions 登记规范第 9 条：事后再挑读法就是自欺）。
- **验证窗口固定 7 天**（含登记当天）。苗头晚两天爆依然算对，所以窗口宁宽勿紧（同第 7 条）。
- **检索写法要具体**。有旧含义或很常见的词，要加限定词：写「蜜雪 冰淇淋 涨价」，不写「涨价」。
  这是 new-term-radar 的教训：「strata」本身的基线太高，看不出新词有没有起来；「niko1221 strata」才看得出来。
- **登记前先核实它还没上过榜**。已经在榜上的不叫苗头，标 ↑ 爆发中，不登记。
- **把握档**：高 / 中 / 低，定义同 CLAUDE.md。**高档占比超过 70% 视为分档失效**，self_check 会报警。
  一般情况下大部分苗头应该是「低」：本来就是在押注还没发生的事。

## 记分：到期当天或之后

| 结果 | 条件 |
|---|---|
| **✅** | 找到窗口内的上榜证据（榜单截图转述、热搜归档站、媒体「冲上热搜」报道），记下上榜日期 |
| **❌** | 按固定检索式查不到任何上榜证据 |
| **⊘** | 登记后发现它在登记前就已经上过榜（登记无效，不计入命中率） |

- **固定检索式**（三条都要查）：`<写法> 热搜`、`<写法> 冲上 热搜`、`<写法> 热榜`。
- ⚠ 「查不到」不等于「没上榜」：WebSearch 有漏网，所以 ❌ 会**略微偏多**。
  这个偏差方向是对我不利的，可以接受；**不得反过来把查不到记成 ⊘**，那样等于给自己免考。
- **提前天数** = 上榜日 − 登记日。命中但提前 0 天，说明登记时它其实已经快爆了，这条的价值低。

## 统计（self_check C10 自动计算）

- 苗头命中率，按把握档拆开。**满 20 条之前不下结论**（同 predictions 的样本门槛）。
- 命中条目的平均提前天数。
- **拿什么对比**：苗头命中率要和「随手挑」的基准比，否则高低都无从判断。
  基准的做法是每周从当天热度最低的话题里抽 1 条登记为「对照」，把握档填「对照」，不参与分档统计。
  差不开，说明苗头判断没有信息量，那就别再写「明日观察预警」。

## 从 new-term-radar 借来的两条判定纪律

1. **和它自己的基线比，不和别的词比**：老话题回温和新话题冒头是两回事，看的是它自己的变化。
2. **还没结算的数据不读**：Google Trends 最后两天的值会乱跳；热榜同理，看排名要看归档的定格值，不看实时滚动值。
   这和期权扫描「收盘口径的判断，不用盘中读数预言结果」是同一条纪律。
