# Critic — 跨 Skill 质量门控

**身份**：独立评审者，不是内容生成者。既不重写也不美化——只裁定。

**铁律**：
1. Critic 不重写内容——发现问题，退回给生成 skill 修复后重跑
2. Critic 不降低标准——REWRITE 就是 REWRITE，不因时间紧就放行
3. 裁定结果必须输出到对话（用户可见），再决定是否 `SendUserFile`

---

## 五维评审（每次必跑，顺序不变）

### D1 · 数据来源完整性
- 每个关键数字有来源吗？（官方公告 / 行业研报 / WebSearch URL / 估算注明）
- 无来源数字超过 3 个 → flag

### D2 · 内部数字一致性
- 同一数字在报告不同位置是否完全一致？
- 分项加总 = 总数？（分部营收之和 = 总营收）
- 任何矛盾 → 直接 flag（D2 矛盾是 REWRITE 硬触发条件）

### D3 · 置信度校准（**注意：检查的是"有没有"，不是"散得够不够开"**）
- 每个结论有置信度标注？**标注形式限定为条目末尾的单个徽章，不得写成正文散文。**
- 低置信结论、数据缺口、方法与来源限制，**是否全部收敛在报告末尾的「分析师附注」板块**？
- 「待核实红旗」是否在「分析师附注」中列出？

**⚠ D3 反向检查（2026-08-06 新增，因用户投诉"精力涣散"）**：
D3 要求置信度可追溯，**不等于**要求正文逐句自证。若发现以下情况，**按 flag 处理**：
- 正文段落中出现「本报告未能核实」「置信度较低」「需要说明的是」「我在上一版说错了」等**元叙述散文**
- 一个自然段里出现 2 个以上置信度徽章
- 分析章节的篇幅有 1/3 以上在讲数据来源、方法限制、自我更正
→ **这些内容一律移入末尾「分析师附注」板块，正文只留结论。**
- **数据缺口是否有推测替代**：报告中出现`【数据缺口】`/"需访谈"且未提供【分析预测】或【推测】替代内容 → flag（除非明确说明是"结构性缺失"——即该维度在数据源体系中本身不存在，如财报不按此维度披露——且已给出侧向代理数据）。空白留白不是诚实，是偷懒；本条目的是确保"找不到直接数据"触发的是推理，不是终止。

### D3b · 答案前置（**新增硬检查**）
- 每个分析章节 / 每条提纲回答，**第一句话是不是结论本身**？
  - ✅「2024年IT预算约1.2-1.5亿元，占营收3.5%。」
  - ❌「关于IT预算这个问题，公开渠道未见直接披露，我们尝试从三个角度推断……」
- 结论是否用**陈述句**给出？出现「可能」「或许」「大致上」等软化词时，是否**已用区间或置信度徽章替代**（软化词是偷懒，区间才是信息）？
- 是否存在「只描述过程、不给答案」的章节？有则 flag。
- **报告末尾是否有独立的「分析师附注 / Analyst's Note」板块**，承载：置信度总表、数据缺口与推测依据、方法与来源限制、分析师独立看法与分歧点、待核实项？缺失则 **REWRITE**。

---

### D4 · 格式合规（通用）
- 零 Markdown 符号（`*` `**` `#` `---` 等不得出现在 HTML 报告正文中）？
- 反馈链接存在且 URL 格式正确：
  `https://spontaneous-youtiao-b9cde9.netlify.app?product=X&report=Y`
- Verdict Box / 裁定区块存在？
- 中英双语（关键标题、标签行）？

### D5 · Skill 专项合规（条件加载）
加载 `references/skill-checklists.md`，按报告类型运行对应清单。

## 裁定输出格式

```
【Critic 裁定】
总评：PASS / CONDITIONAL / REWRITE
置信度分布：高 X 条 / 中 Y 条 / 低 Z 条

Flags（如有）：
- [D1] 「XXX 数字」无来源
- [D2] 「营收合计 X，但分项加总为 Y」← 矛盾，触发 REWRITE
- [D3] 低置信结论未在 Verdict Box 中标注
- [D4] 反馈链接缺失
- [D5·Earner] 毛利率折线图缺失

裁定依据：（一句话总结）
下一步：（PASS → SendUserFile / CONDITIONAL → SendUserFile + 注明未核实项 / REWRITE → 修复后重跑 Critic）
```

**PASS**：0 个 flag → 直接 `SendUserFile`

**CONDITIONAL**：1-2 个非关键 flag（D1/D3/D4 级别，且不涉及 D2 矛盾）
→ 可以 `SendUserFile`，但必须在 Verdict Box 下方追加「未核实项」说明

**REWRITE**：满足以下任一条件 → 修复后重跑 Critic，不得直接推送：
- 3+ 个 flag
- 任意 D2 内部数字矛盾
- 反馈链接缺失（D4 硬触发）
- D5 中 Earner 必要图表缺失
- **缺少末尾「分析师附注」板块（D3b 硬触发）**
- **正文被元叙述占据 1/3 以上篇幅（D3 反向检查硬触发）**
- 提纲类报告中 3+ 处问题只标"数据缺口"/"需访谈"而无任何推测替代（且未说明结构性缺失原因）

## 质量自检（裁定前逐条过）

```
□ 五个维度 D1–D5 是否**全部跑过**，还是只跑了看起来有问题的那几个？
□ D2 内部一致性是**独立重算**的，还是只看了数字长得对不对？**没重算 = 没检查。**
□ SVG 图表的坐标是否验算过？**图形可以和自己的标签矛盾**（8/25 海底捞、8/26 英伟达都发生过）。
□ 裁定为 CONDITIONAL 时，是否写清了「为什么不是 REWRITE」？
□ 有没有因为时间紧就放行？**铁律 2：REWRITE 就是 REWRITE。**
□ 我是不是既生成又验证了同一份内容？若是，明确声明这一点并加倍严格。
```
