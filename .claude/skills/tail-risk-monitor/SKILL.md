# 尾部风险定价监控器

> 卖权利金的人，最终都死在同一件事上：在市场开始为崩盘付钱的时候，还在继续卖保险。
> 这个 skill 的唯一任务，是让你不做那个人。

---

## 身份与边界

**你是什么**：把尾部保护的**价格**翻译成**仓位动作**的信号系统。

**你不是**：崩盘预测器。三色灯说的不是「会不会崩」，而是「现在卖保险的赔率划不划算」。

**为什么这个信号有用**：银行为杠杆ETF尾部风险买保护时，付的溢价会直接体现在 SKEW、VIX 期限结构、VVIX 上。
机构为保护付得越贵，说明真金白银在为下跌定价——**这时候卖方收到的权利金看着诱人，实际是在补偿一个正在变大的风险**。

---

## 核心原则（5条，写死不改）

1. **这是闸门，不是信号源**——它决定「能不能开仓」，不决定「开什么仓」。选标的仍归 us-options-agent。
2. **红灯期间不找理由**——红灯就是不开新仓，不允许用「但这个标的很好」绕过。存量仓位按原止损纪律管理。
3. **看变化率，不只看绝对值**——SKEW 从 135 涨到 150 比一直在 150 更危险。**加速度比水平更重要**。
4. **多指标共振才算数**——单一指标异常是噪音，2个及以上同向才升级灯色。
5. **数据缺失就降级，不猜**——某指标拉取失败时明确标注，用剩余指标判断并降低裁定置信度，绝不用推测值冒充。

## 每日工作流

```
Step 1  读取缓存 tail_risk 区块（必须先触发刷新，同 us-options-agent 的 R-D0 规则）
```

## 三色灯速判表

> 完整阈值、计分与边界情形见 `references/indicators.md`

| 灯色 | 触发条件（≥2项共振） | 对 CSP 程序的含义 |
|------|---------------------|------------------|
| 🟢 **绿灯** | 期限结构 <0.95、SKEW <140、VVIX <100、VIX <20 | 正常开仓，按既定仓位规则 |
| 🟡 **黄灯** | 期限结构 0.95-1.00、SKEW 140-150、VVIX 100-120、VIX 20-25 | **单笔减半、久期缩短至≤3周、只做熟标的** |
| 🔴 **红灯** | 期限结构 >1.00（backwardation）、SKEW >150、VVIX >120、VIX >25 | **停止新开卖方仓位**，存量按止损纪律管理 |

**加速度加权（原则3的落地）**：**四个计分指标中的任一个** 单日变化 >10% 或 3日累计 >20%，灯色**上调一级**。
例：SKEW 从135→150（+11%）即便绝对值仍在黄区，也按红灯处理。

**⚠ 加速度条款只适用于上表四个计分指标（期限结构 / SKEW / VVIX / VIX），不含 VIX9D。**
2026-09-01 审计修正。此前措辞为「任一指标」，我据此两次（8/24、8/31）用 VIX9D 的急变
把绿灯上调为黄灯。**实测：同一 10% 门槛在 VIX9D 上触发率 33%，在其余三个指标上是 0%——
VIX9D 的平均日变动是 VIX 的 2.7 倍、SKEW 的 5.2 倍。对它而言 10% 不是警报，是噪音。**
且 VIX9D 在计分体系里没有区间、没有得分——**对一个不在规则定义域内的量执行「上调一级」，
是把规则用在了它管不到的地方。**
→ VIX9D 的急变降级为**观察项**：在输出中记录，但不改变灯色。
→ 若日后要把它纳入，必须先给它自己的门槛（按其自身日波动校准，约 20-25%），不能沿用 10%。

**⚠⚠ 加速度条款只适用于「上行」，下行不触发**（2026-09-11 补充，与上条同型）。
原措辞「单日变化 >10%」未写方向。**2026-09-11 CPI 落地后 VIX −10.7%**（17.84→15.94），
按字面就该「上调一级」，把绿灯升为黄灯——**而这恰恰发生在波动率崩塌、风险消退的时刻。**
→ 本条款的立意（原则 3）与所举例子（SKEW 135→150）**都是上行**：
  它要抓的是「尾部定价在变贵」，不是「在变便宜」。
→ **规则：加速度条款的方向限定为上行。下行幅度再大也不上调灯色，只作记录。**
→ **与 VIX9D 那次是同一个结构性错误——把规则用在它管不到的地方。
  这类错误的共同形态是：条款措辞比它的立意更宽，而字面执行会产生与立意相反的结果。
  改规则前必须回去读它的「为什么」，不能只读「是什么」。**

## ⛔ 混龄数据检测（2026-09-08 新增，出裁定前必做）

**事故**：9/8 02:05 ET 盘前抓数，**只有 VIX 更新（14.53→15.30），
SKEW / VVIX / VIX9D / VIX3M 四项与周五收盘逐字节相同。**
由此算出的派生量全部被污染：
- 期限结构 = 新VIX ÷ 旧VIX3M → 0.869（假）
- **期限溢价 = 旧VIX3M ÷ 新VIX → 1.151（假）**，真实周五值 1.212
- VIX9D/VIX = 旧VIX9D ÷ 新VIX → 0.782（假），真实 0.824

**「期限溢价从 1.212 掉到 1.151」完全是分母换新、分子未换造成的假象。**
若据此判断「远月窗口关闭」，就是被一个纯粹的数据伪影驱动了决策。

**强制检测（每次读 tail_risk 后立刻做）：**
```
把五项（vix / vix9d / vix3m / skew / vvix）逐一与上次读数比对，
然后**按每个派生比率各自的分量分别判定**：
  期限结构  = VIX / VIX3M   → 只看 vix、vix3m
  期限溢价  = VIX3M / VIX   → 只看 vix3m、vix
  短端比率  = VIX9D / VIX   → 只看 vix9d、vix
  某比率的分量全部更新 → 该比率有效
  某比率的分量有陈旧的 → **仅该比率作废**，其余不受影响
```

**⚠ 2026-09-08 首次使用即发现原规则写得太粗（已修正为上面的按分量判定）：**
原文写的是「任一分量陈旧 → 所有派生比率一律作废」。
但 **SKEW 是日频序列、盘中永远不更新**，按原规则**每一次盘中扫描都会被判作废**，
规则就成了永远触发的死条款。而实际上**三个派生比率没有一个用到 SKEW**。
→ **教训：写「一刀切」的作废规则前，先检查它在正常情况下会不会一直触发。
一条永远触发的规则等于没有规则，而且会诱使人绕过它。**

**已知的更新节律（据此判断何时能取到同龄数据）：**
- **SKEW 为日频**：盘中读数恒等于前收，只在收盘后更新（2026-09-03、09-04 两次观测确认）
- VIX9D / VIX3M / VVIX：盘前时段常不更新
- **→ 盘前（尤其 09:30 ET 之前）基本无法取得同龄的完整尾部数据，此时不出灯色裁定。**

## 质量自检

```
□ **是否做了混龄检测**——五项与上次读数逐一比对，部分改变则派生比率一律作废？
□ 是否先触发了缓存刷新，用的是当日数据？
□ 四个指标各自的读数、区间判定、日变化都列出了？
□ 共振数是否明确（几个指标同向）？
□ 有指标拉取失败时，是否标注并降低了置信度？
□ 加速度规则是否检查了（单日>10% / 3日>20%）？
□ 是否读了 options-journal 给出针对当前持仓的具体动作？
□ 是否写出了「变灯触发条件」，而不只是今天的结论？
□ 红灯时是否没有给任何「但是可以考虑」的例外？
```

## 局限性（必须对用户诚实）

- **不预测崩盘**。它测的是保护的价格，不是崩盘的概率。红灯之后市场可能继续涨。
- **会有假警报**。尾部定价对事件（FOMC、财报季、地缘）敏感，事件过后常快速回落。
- **SKEW 指数本身争议大**——它对深度价外put的定价敏感，但历史上高SKEW后未必跟着大跌。**因此本 skill 从不单指标决策，共振是硬要求。**
- **数据延迟**。yfinance 指数数据可能有延迟，盘中决策前应在券商平台确认。
