# 已知失效场景与方法论清单增量

> 由 SKILL.md 在怀疑归因结论过度拟合、或需要更新方法论清单时加载。
> **本文件是 append-only 的活文档**，`Burry 清单` 直接读它。

---

## 第一部分：已知失效场景（显式写出，避免过度拟合）

### F1 · 言行脱节
**历史上多次公开表达宏观悲观但未对应落地仓位。**
→ **归因不能只看发言，必须以持仓变化为主证据。**
→ 当发言与持仓不一致时，**报告必须把这个不一致本身写出来**，而不是选一个信。

### F2 · 不可复制性
**高浓仓位 + 高换手的组合特征，即使复制持仓也不代表复制了他的资金结构和风险承受能力。**
他的资金是「friends and family」性质，赎回压力与机构资金完全不同。
→ **本框架的价值在于理解决策逻辑，不是生成跟单信号。**
→ 任何输出中出现「建议买入/卖出/加仓」即违反边界。

### F3 · Tier 2 数据的结构性局限
2025-11 之后若确无强制披露，则**任何「未披露仓位」都无法证伪**。
newsletter 有订阅付费商业动机，**选择性披露方向明确**。
→ **归因报告需明确「已知」与「未知」的边界，不能用沉默当作证据。**

### F4 · 13F 看不见空头
**「大空头」的空头部位在 13F 上完全不可见。**
→ 任何关于「他在做空什么」的归因，**13F 不是证据来源**。若无 Tier 1 证据，该结论只能进「未知」栏。

### F5 · 期权按名义市值披露
13F 对期权披露的是标的名义市值，不是权利金。
→ **与股票仓位并列排序会严重夸大期权仓位。必须单列，不与股票同表。**
→ 「某期权仓位占组合 20%」这句话在 13F 语境下几乎必然是误读。

### F6 · 季末快照掩盖季中动作
季中建仓再清仓完全不可见，**换手率被系统性低估**。
→ 报告标题措辞必须是「季末持有什么」，**不能写成「这季做了什么」**。

### F7 · 45 天滞后
看到数据时持仓可能已变。
→ 归因结论描述的是**备案期末的状态**，不是当下状态。**报告日期与数据期间必须同时标注。**

### F8 · L1 的必要不充分陷阱
**「我能算出它便宜」≠「他因为便宜才买」。**
全市场同期有几百家同样便宜的公司他没买。
→ **L1 的结论上限是「符合选股标准」，不是「因此他买了」。**

### F9 · 清仓归因的方向性偏差
清仓在 13F 上只表现为「消失」，价值证伪与纪律触发长得一模一样。
**若默认判成证伪，则在基金注销那一季会得出「认错率 100%」的荒谬结论。**
→ 已在 `attribution-framework.md` 中改为「由基金层面事件开关决定」。
→ **⚠ 反向风险同样存在**：若过度使用「纪律触发」这个出口，会系统性低估认错率。
   **认错率统计必须同时给出含/不含基金事件季两个口径。**

### F10 · 后见之明拟合
用「扫描器与实际持仓的重合度」去反向调筛选阈值，会得到一个只能解释过去的筛选器。
→ **`Burry 校验` 只跑一次，结果只作诊断，不作调参依据。**

### F11 · 分位数的样本偏差
分位数只能在有完整 XBRL 数据的样本内算，而缺数据者系统性偏小盘偏便宜。
→ 排除它们会抬高「便宜」的门槛。**缺数据组单列，不参与计算也不剔除。**
→ 元教训：**任何「检测到异常就删掉异常」的修法，都要问「删完之后样本还代表原问题吗」。**

### F12 · 二手源期间错标
媒体转述的持仓/财务数字高发期间错标（本会话已遇三次：海底捞、英伟达、美团）。
→ **必须回到 13F 原文。**
→ 判别法（已验证三次有效）：**用已确认的独立事实去戳二手源，倒推不一致则弃用该来源。**

## 第二部分：方法论清单增量（append-only）

> 归因中出现现有清单未覆盖的新模式时，**先标为待补充项**，不要临场发明规则塞进框架。
> 经过至少两个季度重复出现后，再提升为正式检查项。

### 格式
```
[YYYY-MM-DD] [待补充 / 已转正] 模式名称
  触发场景：
  暂定判据：
  待验证：需要在哪几个季度看到重复出现才转正
```

### 记录

```
[2026-08-28] [待补充] L3 默认判定方向的双向风险校准
  触发场景：建档时发现原规格「清仓默认判证伪」与其声明目的（防止高估认错率）方向相反
  暂定判据：改为由「当季有无基金层面事件」开关决定默认值
  待验证：拿 2025Q4 / 2026Q1 实际数据各跑一遍，确认修正后没有走向另一个极端
          （即把所有清仓都归为纪律触发，从而系统性低估认错率）。
          验证方法：分别用两种默认值跑同一季，比较认错率差异是否超过 20 个百分点。
```

```
[2026-08-28] [待补充] Tier 1 边界的制度性不确定
  触发场景：Scion 注销投顾注册，但 13F 义务由持仓规模而非注册状态触发
  暂定判据：每次运行从 EDGAR submissions 发现最新 13F-HR 期间，不写死日期
  待验证：观察 2025Q4 / 2026Q1 是否出现新的 13F-HR。
          若出现 → Tier 1 边界后移，Tier 2 的适用范围相应收窄，需回溯修订已出报告。
          若连续两季未出现 → 可将「Tier 1 已终结」的置信度从「中」提升到「高」，但仍不写死。
```

```
[2026-08-28] [待补充] 扫描器覆盖范围与真实选股范围的缺口量化
  触发场景：EDGAR 仅覆盖美股，而他历史上做过波兰、英国、墨西哥小盘股
  暂定判据：每次扫描输出抬头显式声明范围收窄
  待验证：统计其历史持仓中非美股主体的占比，把「收窄程度」从定性说法变成一个数字。
          该数字应写入扫描输出，让使用者知道漏掉的大概是多大一块。
```

## 第三部分：出报告前的最后一道闸

**以下任一条成立，报告不得交付：**

- [ ] 存在未标 Tier 的归因结论
- [ ] Tier 2 材料被单独用来支撑某条结论
- [ ] L3 清仓归因写在「查基金层面事件」之前
- [ ] 出现「建议买入 / 卖出 / 加仓 / 跟随」字样
- [ ] 「未知」栏为空
- [ ] 认错率只给了一个口径（未区分含/不含基金事件季）
- [ ] 期权仓位与股票仓位在同一张表里按市值排序
- [ ] 标题或结论写成「他这季做了什么」而非「他季末持有什么」
- [ ] 扫描输出静默剔除了数据不完整的公司
- [ ] 临场发明了一条不在清单里的判据（应标为待补充项）
