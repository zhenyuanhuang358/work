## 事故一 · VIX9D 的 10% 门槛（2026-09-01，全仓审计发现）

加速度条款原文写「任一指标单日变化 >10% → 上调一级」，我据此两次（8/24、8/31）用 VIX9D
把绿灯判成黄灯。实测各指标平均日变动：

| 指标 | 平均日变动 | 10% 门槛 = 常态的几倍 | 超 10% 触发率 |
|---|---|---|---|
| **VIX9D** | **6.44%** | 1.6 倍 | **33%** |
| VIX | 4.78% | 2.1 倍 | 0% |
| VVIX | 3.76% | 2.7 倍 | 0% |
| 期限结构 | 2.68% | 3.7 倍 | 0% |
| SKEW | 1.38% | 7.2 倍 | 0% |

**VIX9D 的波动是 SKEW 的 4.7 倍。同一个门槛套上去触发率 33%——那不是警报，是噪音。**
且 VIX9D 在计分体系里没有区间、没有得分——**对不在规则定义域内的量执行「上调一级」，是越界。**

→ VIX9D 降为观察项。若日后纳入，必须按其自身日波动单独校准门槛（约 20–25%），不得沿用 10%。
→ **追认 8/24 与 8/31 两次黄灯均为误判。** 方向是过度保守，但不是不修的理由——
  反复假警报会让灯色失去意义，下次真该黄灯时它已经不值钱了。

**⚠ 残留问题（2026-09-15 实测，已知但不改）**：即便剔除 VIX9D，剩下四个计分指标之间
10% 门槛仍相当于各自常态的 **2.1 至 7.2 倍，跨度 3.4 倍**。实测触发率 0%–4.5%，尚未造成误判，
**故记录为已知脆弱点而不改——无证据的改动等于调参。若日后 VIX 端出现假警报，从这里查起。**

## 事故二 · 混龄「一刀切作废」（2026-09-08，首次使用即发现）

原规则：「五项中任一分量陈旧 → 所有派生比率一律作废」。
**但 SKEW 是日频序列、盘中永远不更新**，按原规则每一次盘中扫描都会被判作废。
而实际上三个派生比率（期限结构、期限溢价、短端比率）**没有一个用到 SKEW**。

→ 改为**按分量判定**：某比率的分量全部更新则该比率有效；分量有陈旧的则仅该比率作废。

**教训：写「一刀切」的作废规则前，先检查它在正常情况下会不会一直触发。
一条永远触发的规则等于没有规则，而且会诱使人绕过它。**

## 事故三 · 加速度条款未限定方向（2026-09-11，实盘当天发现）

原措辞「单日变化 >10%」未写方向。2026-09-11 CPI 落地后 **VIX −10.7%**（17.84→15.94），
按字面就该「上调一级」把绿灯升为黄灯——**而这恰恰发生在波动率崩塌、风险消退的时刻。**

条款的立意（原则 3）与它自己所举的例子（SKEW 135→150）**都是上行**：
它要抓的是「尾部定价在变贵」，不是「在变便宜」。

→ **加速度条款方向限定为上行。下行幅度再大也不上调灯色，只作记录。**

## 事故四 · 「≥2 项共振」被架空（2026-09-15，规则回放发现）

`rule_replay.py` 回放 2026-08-18 至 09-15 共 22 个交易日：

```
term_structure   绿 100.0%   黄   0.0%   红   0.0%    观测 0.80–0.90
skew             绿   0.0%   黄  68.2%   红  31.8%    观测 142.93–154.49
vvix             绿  95.5%   黄   4.5%   红   0.0%    观测 82.90–102.66
vix              绿 100.0%   黄   0.0%   红   0.0%    观测 14.32–17.84

非绿档组合分布：
  skew                     21 天   95.5%
  skew + vvix               1 天    4.5%
```

**SKEW 在 22/22 天全部处于非绿档**——最低值 142.93 仍高于绿档上界 140。

> **后果：「≥2 项共振才变灯」这条硬要求，在整个观测区间内实际等价于「≥1 个其他指标越线」。**
> SKEW 常驻占据一个共振名额。**我每天只看当天一张表，从未把多日叠起来看过，因此三周没发现。**

**造成的误判**：2026-09-10 VVIX 从 98.20 升破 100，我写「两项共振达到变灯硬要求」判黄灯。
那天**只有 VVIX 一项相对自身常态异常**，SKEW 只是维持它三周以来的常态。
次日 VIX −11%、VVIX 回落 91.28，「黄灯持续不到一个交易日」——那确实是噪音，
而原则 4 本来就是为了滤掉这种噪音而存在的。

### 为什么修法是「剔除常驻项」而不是「调高 SKEW 阈值」

原则 4 的立意是「单一指标异常是噪音，2 个及以上同向才算数」。
**「异常」的定义要求它相对自身常态是异常的。一个持续三周不变的状态不是异常，是基线。**
把基线当异常计入共振，等于把门槛降了一半。

调高 140/150 是凑答案（profile 1.1p：阈值该不该调，看的是判别式对不对，不是结果好不好看）。
**在共振计数层面剔除常驻项才是判别式层面的修正**——与 VIX9D 降为观察项是同一个处理。

### 历史反事实检验（任何规则修正之前必做）

对 22 个交易日回放「剔除 SKEW 后」的灯色：

```
2026-09-10   含SKEW 2/4 → 🟡    剔除后 1/3 → 🟢    ← 唯一改变
其余 21 天    完全不变
```

**外科式修正，只移除一次已被次日证伪的假警报，不误伤其余任何一天。**
这是判断一个规则修正是否正确的标准做法——**改动前先回放，看它会改变历史上的哪几天，
以及那几天的改变是对是错。**

### SKEW 阈值本身的长期问题

140/150 是一个**绝对水平**阈值，而 SKEW 的中枢会随年份漂移——当前中枢约 148。
长期解法是改用**滚动分位数分档**，但需要远长于 22 天的历史才能校准。
**暂不改，先用常驻项剔除兜住。数据窗口够长时重新评估。**

### ⚠ 常驻不等于无意义

SKEW 长期高企本身是有信息的（机构在持续为尾部保护付费）。
它应当进入**报告正文的叙述**，只是不进入**共振计数**。**二者是两件事，不要因为剔除就不提它。**

## 事故五 · 期限溢价规则从未被写进任何文件（2026-09-15，阈值漂移检查发现）

**期限溢价 VIX3M/VIX ≥ 1.20 这条规则，我每天都在用，用它做「不开新仓」的裁定，
但它此前从未被写进任何 skill 文件，只活在会话上下文里。**

回放工具的阈值漂移检查抓到了它——脚本里有 1.20，SKILL.md 里找不到。

**这是 profile 1.5「上下文压缩后信息丢失」的重演，而且更危险：
一条高频使用、且直接决定开不开仓的裁定规则，一次上下文压缩就可能整条消失，或悄悄漂移成别的数。**

实测（22 个交易日）：开窗 8 天（36.4%），区间 1.106–1.247。**既非死条款也非恒触发，判别力正常。**
有实际裁定记录佐证：2026-09-03 曾显式写「不是因为期限溢价（1.207 已达标）」而以其他理由不开仓。

→ **通用规则：凡是我在对话里反复引用、并用于裁定的阈值，必须在 skill 文件里有一份。
  判据很简单——如果这个数字只存在于我的记忆里，它就已经在漂移了。**
→ `rule_replay.py` 的第 6 项检查（阈值漂移）就是为了持续抓这类问题。
